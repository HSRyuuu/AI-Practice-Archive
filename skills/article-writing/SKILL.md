# 아티클 작성 (Article Writing)

일반적인 AI 출력물이 아닌, 실제 사람이나 브랜드처럼 들리는 장문 콘텐츠를 작성합니다.

## 사용 시점

- 블로그 포스트, 에세이, 런치 포스트, 가이드, 튜토리얼, 뉴스레터 초안 작성 시
- 메모, 녹취록, 조사 자료를 정제된 기사로 변환할 때
- 예시를 통해 기존 창업자, 운영자 또는 브랜드의 보이스를 재현해야 할 때
- 이미 작성된 장문 카피의 구조, 호흡, 근거를 보강할 때

## 핵심 규칙

1. 구체적인 것부터 시작하세요: 예시, 결과물, 일화, 수치, 스크린샷 묘사 또는 코드 블록을 먼저 제시합니다.
2. 설명은 예시 다음에 하세요. 예시 앞에 장황하게 설명하지 않습니다.
3. 군더더기 없는 짧고 직접적인 문장을 선호하세요.
4. 확인된 출처의 구체적인 수치를 사용하세요.
5. 전기적 사실, 회사 지표, 고객 사례 등을 절대 지어내지 마세요.

## 보이스 캡처 워크플로우

사용자가 특정 보이스를 원할 경우, 다음 중 하나 이상의 자료를 수집하세요:
- 발행된 기사
- 뉴스레터
- X / LinkedIn 포스트
- 문서 또는 메모
- 간략한 스타일 가이드

그다음 아래 항목을 추출합니다:
- 문장 길이와 리듬
- 문체가 격식 있는지, 대화체인지, 혹은 날카로운지 여부
- 선호하는 수사적 장치 (괄호, 리스트, 단문, 질문 등)
- 유머, 의견 제시, 반골 기질(contrarian)에 대한 허용 범위
- 포맷 습관 (헤더, 불렛 포인트, 코드 블록, 인용구 등)

참고할 보이스 자료가 없다면, 과장 없이 실용적이고 구체적인 '운영자 스타일(operator-style)' 보이스를 기본값으로 사용합니다.

## 금지된 패턴

다음과 같은 표현은 삭제하고 다시 작성하세요:
- "오늘날 급변하는 환경 속에서..."와 같은 상투적인 도입부
- "게다가(Moreover)", "더 나아가(Furthermore)"와 같은 불필요한 접속사
- "게임 체인저(game-changer)", "최첨단(cutting-edge)", "혁신적인(revolutionary)"과 같은 과장된 표현
- 근거 없는 모호한 주장
- 제공된 맥락에 근거하지 않은 이력이나 신뢰성 주장

## 작성 프로세스

1. 대상 독자와 목적을 명확히 합니다.
2. 섹션별로 하나의 목적을 가진 골격(outline)을 잡습니다.
3. 각 섹션은 증거, 예시 또는 상황 묘사로 시작합니다.
4. 다음 문장이 존재할 가치가 있는 경우에만 내용을 확장하세요.
5. 템플릿 같거나 자화자찬하는 표현은 모두 제거합니다.

## 구조 가이드

### 기술 가이드
- 독자가 얻을 수 있는 이득을 먼저 밝히며 시작합니다.
- 모든 주요 섹션에 코드나 터미널 예시를 포함합니다.
- 단순한 요약이 아닌, 구체적인 실행 방안(takeaways)으로 마무리합니다.

### 에세이 / 오피니언
- 긴장감, 모순 또는 날카로운 관찰로 시작합니다.
- 섹션당 하나의 논점을 유지합니다.
- 주장을 뒷받침할 수 있는 예시를 사용합니다.

### 뉴스레터
- 첫 화면에서 시선을 사로잡아야 합니다.
- 일상적인 신변잡기가 아닌, 통찰과 업데이트를 적절히 섞습니다.
- 명확한 섹션 라벨과 훑어보기 좋은 구조를 사용합니다.

## 품질 검수

전달하기 전에 다음 사항을 확인하세요:
- 사실 관계가 제공된 출처와 일치하는지 확인
- 미사여구와 기업용 상투어 제거
- 보이스가 제공된 예시와 일치하는지 확인
- 모든 섹션이 새로운 정보를 담고 있는지 확인
- 대상 플랫폼에 맞는 포맷팅 확인
