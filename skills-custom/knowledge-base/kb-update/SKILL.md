# KB Update — 기존 문서 업데이트

사용자가 이미 알고 있는 문서를 업데이트할 때 사용한다.

> **핵심 원칙**
> 1. LLM 자체 지식 생성 금지 — 사용자가 제공한 구체적 내용만 추가한다.
> 2. 반드시 A 또는 B 중 하나를 제시 — 다른 선택지 없음.

---

## Step 0. 볼트 경로 확인 + 스키마 로드

1. `~/.config/kb/config.json`을 읽어 `kb_root` 경로를 확인한다.
2. 파일이 없거나 `kb_root`가 없으면 사용자에게 볼트 경로를 물어본 뒤 저장한다.
3. `{kb_root}/SCHEMA.md`를 읽어 폴더 구조를 파악한다.
4. `{kb_root}/.claude/CLAUDE.md`를 읽어 컨벤션을 확인한다.
5. 없으면 에러: **"`/kb-setup`을 먼저 실행하세요."**

---

## Step 1. 관련 문서 탐색

사용자 입력에서 키워드를 추출하고, 아래 순서로 관련 문서를 탐색한다:

1. **00_index_{Name}.md 탐색**: 각 폴더의 00_index_{Name}.md를 읽어 한줄 요약에서 관련 문서를 찾는다.
2. **qmd 검색** (설치 시): `qmd search "{키워드}" 2>/dev/null`
3. **frontmatter 필터**: tags/group으로 범위를 좁힌다.
4. **위키링크 따라가기**: 발견된 문서의 위키링크를 따라가며 관련 문서를 추가 탐색한다.

---

## Step 2. 결과 제시

반드시 아래 두 가지 중 하나만 제시한다:

### A. 문서 발견

> "→ **[[{경로/문서명}]]**을 업데이트하겠습니다. 확인?"

- 후보가 여러 개면 목록을 제시하고 사용자가 선택하도록 한다.
- 승인 → Step 3

### B. 문서 없음

> "적절한 문서가 없습니다. `/kb-add`로 추가할까요?"

- 사용자가 동의하면 `/kb-add` 워크플로우로 전환한다.

---

## Step 3. 문서 업데이트

1. 대상 문서를 읽는다.
2. 사용자가 제공한 내용을 적절한 위치에 추가/수정한다.
3. frontmatter `tags`가 변경되었으면 업데이트한다.

---

## Step 4. 후처리

1. 해당 폴더 `00_index_{Name}.md`의 한줄 요약을 갱신한다 (내용이 바뀌었으면).
2. 관련 문서 간 위키링크 교차 참조를 갱신한다.
3. qmd 인덱스 리빌드: `qmd index rebuild 2>/dev/null || true`
4. Git 커밋:

```bash
cd {kb_root}
git add -A
git commit -m "kb: update '{문서명}'"
```
